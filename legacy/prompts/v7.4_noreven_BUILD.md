# Ревень — временное исключение из каталога WF-2

Проект BURATINO · 2026-08-31 · решение Никиты: полевых фото ревеня нет, SKU предположительно
снят с производства → убрать вкус из выборки **временно**, до уточнения у заказчика.

## Что сделано

Одна точка правки: **фильтр строк каталога в момент сборки запроса**. Ревень выпадает
одновременно из справочника эталонов (картинки не уходят в модель) и из `enum` схемы
(имя недоступно для вывода) — модель о вкусе не знает вовсе.

Каталог, филлер, лист `Catalog`, WF-3 и синк **не тронуты**: строки ревеня остаются в
источнике, файлы продолжают жить в Files API. Возврат — вычёркивание одного ключа.

Патч продублирован в обеих ветках WF-2 и в обеих нодах сборки (проход 1 и проход 2):

| Файл | Ноды |
|---|---|
| `WF2_v4.3_noreven.json` | «Сборка запроса Gemini», «Сборка запроса Pro» |
| `WF2_v4.4_OR_urls_noreven.json` | «Сборка запроса Gemini», «Сборка запроса Pro» |
| `WF2_v4.4_pro_node_noreven.js` | исходник Pro-ноды v4.4 отдельным файлом |

Оригиналы (`WF2_v4.3_sheets_cold.json`, `WF2_v4.4_OR_urls.json`, `WF2_v4.4_pro_node.js`)
остались нетронутыми — это и есть точка отката.

## Код патча

Вставляется **сразу после гарда** `if (rowsAll.length < 20) throw …` — гард продолжает
считать ПОЛНЫЙ каталог, иначе исключение маскировало бы протухшую реплику.

```js
// ── ВРЕМЕННОЕ ИСКЛЮЧЕНИЕ ПОДВИДОВ ИЗ КАТАЛОГА (31.08.2026) ──────────────────
// Ревень снят с выборки: полевых фото вкуса нет, SKU предположительно снят с производства.
// Пока ключ в списке — подвида нет НИ в справочнике эталонов, НИ в enum схемы,
// то есть модель о нём не знает вовсе (лечит имя-паразит: ревень без хозяина на полке
// липнул к самой розовой группе — персик/клубника).
// ВЕРНУТЬ РЕВЕНЬ = очистить массив:  const EXCLUDE_KEYS = [];   ← и больше ничего.
// Сравнивается базовый key: точное совпадение ИЛИ key + '__<вариант>' — ловит __rot, __kz, __ru,
// __pet1000, __can900, и НЕ заденет посторонний подвид с похожим началом имени.
const EXCLUDE_KEYS = ['aitea_reven'];
const isExcluded = r => { const k = String(r.key || ''); return EXCLUDE_KEYS.some(p => k === p || k.startsWith(p + '__')); };
```

Дальше — по одной строке на ноду:

**«Сборка запроса Gemini»** (обе ветки):
```js
let rows = rowsAll;                              // было
let rows = rowsAll.filter(r => !isExcluded(r));  // стало
```

**«Сборка запроса Pro»** (обе ветки) — там `rowsAll` используется напрямую:
```js
const rowsAll = $('Каталог брендов: Config')…    // было
let   rowsAll = $('Каталог брендов: Config')…    // стало (const → let)
rowsAll = rowsAll.filter(r => !isExcluded(r));   // добавлено следом за блоком выше
```

**Маркеры версии** (чтобы прогоны без ревеня отличались в логах):
`prompt_version: 'v7.4-nopairs'` → `'v7.4-nopairs-noreven'`;
`pass2_version: 'v9-groups'` / `'v9-groups-OR-urls'` → `…-noreven`.

## Как применить в живом n8n

- **Вариант А (быстрый, если живой WF совпадает с файлом):** Import from File в ЖИВОЙ
  воркфлоу — ID сохраняется, указатели и вебхуки не перевешиваются.
- **Вариант Б (безопасный, если живой WF ушёл вперёд файла):** открыть две Code-ноды и
  внести три правки руками по фрагментам выше. Правки локальные, ничего вокруг не задевают.

Вариант Б предпочтителен для ветки `-urls`: последняя правка билдера делалась в UI и в
файле может быть не всё.

## Проверка после применения (2 минуты, без замера)

1. Прогнать любое фото → в выводе ноды сборки `refs_count` **47** вместо 49
   (в каталоге две строки ревеня: `aitea_reven`, `aitea_reven__rot`).
2. `prompt_version` в логе оканчивается на `-noreven`.
3. В `SUBTYPES` 21 имя вместо 22 — проверяется тем же выводом ноды.
4. Ошибки гарда быть не должно: 49 строк каталога он видит по-прежнему.

## Побочки — названы один раз

- **Реальный ревень на полке станет `null` или уедет в чужое розовое имя.** Это тихая
  ошибка: в отчёте не будет пометки «неизвестный вкус», просто пустой подвид или лишняя
  единица у персика/малины. Пока считаем, что SKU мёртв; если заказчик подтвердит, что
  ревень в ходу — возврат обязателен и срочный.
- **Первый прогон после правки — холодный implicit-кеш** (состав справочника = префикс
  запроса изменился). Время и цену первого прогона в сравнение не брать.
- WF-3 продолжит ежедневно перезаливать файлы ревеня в Files API — безвредно, зато возврат
  мгновенный: URI живые, ничего заново заливать не нужно.
- Экономия префилла — 2 эталона из 49 (~4%). Ради скорости это не делается, эффект в другом.

## Что это должно починить и как мерить

Гипотеза (из `buratino-vision-findings`): персик→ревень в проходе 1 — это **имя-паразит**,
у которого нет хозяина на полке. Без имени в enum паразит исчезает по построению.

Замер — по правилу «2 прогона на вывод», одна переменная:

1. **IMG_0644** ×2 — контроль розовой зоны на документе (там персик×3 и клубника×3 ПЭТ 0,5).
2. **IMG_0643** ×2 — эталон 66 юнитов, там персик→ревень ×5 воспроизводился стабильно.

Смотреть: (а) ушёл ли персик→ревень **из прохода 1**; (б) не встал ли на его место новый
паразит (кандидаты — малина, клубника, гуава: розовая пара станет тоньше на одно имя, но
конкуренция внутри оставшихся никуда не делась); (в) счёт юнитов не поехал.

Если (а) да и (б) нет — открывается то, ради чего это и делается: **гейт розовой зоны
можно сузить, а на части фото проход 2 выключить совсем** (сейчас IF «Pro-проход включён?»
стоит в `true` — второй проход идёт всегда). Это уже отдельная серия, вместе с этой не
мешать.
