# Замеры BURATINO — протокол и формат

Папка: `bench/`. Прогоны кладутся в `bench/runs/`, скорер — `score_runs.py`,
эталон разметки контрольного кадра — `GT_aitea_5shelf.json`.

## 1. Правила серии

Серия — это N прогонов **одного и того же кадра** при **полностью замороженной** системе.

Между прогонами серии НЕ трогаем:
- лист Catalog и файлы на Диске, филлер не гоняем;
- ноды WF-2 (`EXCLUDE_KEYS`, промпты, пороги);
- модель и её параметры.

Ещё:
- Слать **тот же самый файл фото** — пересылать одно и то же сообщение, а не переснимать
  и не пережимать. Другой байтовый вход = другой замер.
- **Первый прогон после любой правки каталога — холодный кеш.** Помечать `cold` и в
  статистику не брать (видно по `_usage.cached_tokens` — у холодного он null или маленький).
- Прогоны подряд, в один заход. Не смешивать серии, снятые в разные дни.
- **N = 5.** Меньше трёх — вообще не разговор: 31.08 два раза приняли шум за последствия правок.

## 2. Что собирать с каждого прогона

Нужны выводы ДВУХ нод, целиком, с `_detect.boxes_raw`:

- **проход 1** — нода, где лежит распарсенный результат первого вызова (`_detect`, `_usage`);
- **финал** — нода после прохода 2 (`_detect` уже переписанный, плюс `_pass2`).

`items` недостаточно: там нет координат, а ошибки считаются **по позициям** — только так
видно, что проход 2 сдвинул выравнивание или переименовал группу целиком.

## 3. Формат файла прогона

Один файл на прогон, `bench/runs/run_NN.txt`, UTF-8:

```
RUN 03 | exec 12345 | 2026-09-01T09:14:22Z | 1:47 | catalog 48 | refs 46 | EXCLUDE=[aitea_reven] | frame AITEA_5SHELF | warm
PASS 1:
{ ... вывод ноды прохода 1 целиком ... }

PASS 2:
{ ... вывод финальной ноды целиком ... }
```

Шапка — одна строка, необязательная, но с ней разбор в разы полезнее. Поля: номер прогона,
id выполнения n8n, время старта, длительность, строк в каталоге, `refs_count`, содержимое
`EXCLUDE_KEYS`, метка кадра, `warm`/`cold`.

Скорер терпит: `PASS1:` и `PASS 2 :`, блоки в любом порядке, мусор после JSON, файл без шапки.

## 4. Проверка на дубль

31.08 два «разных» прогона оказались одним и тем же ответом прохода 1 — совпали все 58 боксов
и `output_tokens`. Скорер такое ловит сам и печатает `⚠ ДУБЛЬ прохода 1`. Если увидел —
проверь id выполнения: скорее всего скопирован один и тот же execution.

## 5. Запуск

```
python3 bench/score_runs.py                 # всё из bench/runs/
python3 bench/score_runs.py "bench/runs/serie2_*.txt"
```

Печатает по каждому прогону: ошибки подвида после прохода 1, ошибки в финале, сколько чужих
единиц просочилось, `subtypes_changed`, `needs_review`, выходные токены, геометрический якорь
формата — и снизу разброс по серии (мин / медиана / макс / σ) отдельно для прохода 1 и финала.
Ниже — поимённый список ошибок по позициям.

Разделение «проход 1 / финал» бесплатно отвечает на вопрос, окупается ли проход 2:
если медиана финала не ниже медианы прохода 1 — он только перемешивает ошибки.

## 6. Эталон разметки

`GT_aitea_5shelf.json` — кадр `AITEA_5SHELF`, 5 полок, 53 единицы AI TEA + 5 чужих банок
(1 серебристая слева на полке 1, 4 Zigi-Чай на полке 2). Порядок в каждой полке — слева
направо по `box_2d[1]`. Для нового контрольного кадра делается такой же файл.

## 7. Приложение: нода-сборщик (чтобы не копировать руками)

Временная Code-нода в конец WF-2, `onError: continue`. Имя ноды прохода 1 подставить своё —
в живом WF имена с суффиксом «1».

```js
const P1 = (() => { try { return $('Парсинг прохода 1').first().json; } catch (e) { return null; } })();
const P2 = $input.first().json;
const slim = o => o && ({
  detect: o._detect && {
    boxes_total: o._detect.boxes_total, foreign_units: o._detect.foreign_units,
    slivers_dropped: o._detect.slivers_dropped, format_null: o._detect.format_null,
    anchor: o._detect.format_geo && o._detect.format_geo.anchor,
    boxes_raw: o._detect.boxes_raw,
  },
  usage: o._usage || null,
  pass2: o._pass2 || null,
});
return [{ json: { _bench: {
  run: $execution.id, ts: new Date().toISOString(), frame: 'AITEA_5SHELF',
  pass1: slim(P1), pass2: slim(P2),
} } }];
```

Дальше вывод этой ноды копируется одним блоком вместо двух.
