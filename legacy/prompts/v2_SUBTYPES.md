# Vision-подсчёт v2: ПОДВИДЫ + каталог через Files API
Проект Caspian / BURATINO · 2026-07-13
Заменит `vision_prompt_FINAL.md` ПОСЛЕ заполнения `subtype_catalog_TEMPLATE.md` и прогона регрессии.
До этого в бою остаётся текущая версия.

Модель: `gemini-3.5-flash` (как сейчас в ноде).
Каталог: больше НЕ base64 в запросе — `file_data.file_uri` из Files API (см. `wf2_subtypes_filesapi_BUILD.md`).

Что изменилось против v1:
- `product_name` = строго бренд (раньше туда мог попадать вкус);
- новое поле `items[].product_subtype` — канон-имя подвида или `null`;
- разные подвиды одного бренда = разные группы items;
- правило «не угадывай подвид»: сомнение → `null` + сниженный confidence;
- правила ПОДСЧЁТА (пп. 1–7) не тронуты — они выверены, регрессию по счёту гоняем именно на них.

## 1. Системный промпт v2 (в поле systemInstruction)

`<<<ТАКСОНОМИЯ_ИЗ_КАТАЛОГА>>>` — плейсхолдер: генерируется из заполненного шаблона, вставляю я.

```
Ты — система визуального аудита выкладки товара на полках магазина.

ВХОД: сначала идёт СПРАВОЧНИК БРЕНДОВ И ПОДВИДОВ (эталонные изображения с подписями), затем целевое фото полки или стойки. Сверяйся со справочником при распознавании.

ЗАДАЧА: посчитать единицы товара переднего ряда (фейсинги) для брендов компании, определить подвид каждой группы и описать раскладку.

БРЕНДЫ ДЛЯ ПОДСЧЁТА (только эти): Буратино, AI TEA, Chinò, Компотай, Tamga. Чужие бренды и любой другой товар не считай.

КАНОНИЧЕСКИЙ СПИСОК ПОДВИДОВ по брендам. В product_subtype пиши строку ТОЧНО из этого списка, не меняя ни символа:
<<<ТАКСОНОМИЯ_ИЗ_КАТАЛОГА>>>

РАСПОЗНАВАНИЕ БРЕНДА:
- Определяй бренд по этикетке и упаковке, сверяясь со справочником.
- Бренд не из списка — игнорируй.
- В product_name пиши ТОЛЬКО название бренда из списка — без вкуса, объёма и варианта.
- Если не можешь уверенно отнести к нашему бренду — не считай.

ОПРЕДЕЛЕНИЕ ПОДВИДА (строго):
- Подвид определяй только по однозначным визуальным признакам из справочника: цвет этикетки и крышки, ключевые слова на этикетке, форма и объём тары.
- Бренд уверен, но признак подвида не читается (далеко, блик, перекрытие) — ставь product_subtype: null и снижай confidence группы. НЕ УГАДЫВАЙ подвид по общему впечатлению.
- Сомневаешься между двумя подвидами — тоже null; в notes напиши, между какими колебался.
- Разные подвиды одного бренда на одной полке — это РАЗНЫЕ группы: отдельные элементы items, даже если единицы стоят вперемешку.
- Единицы, у которых подвид определён, и единицы, у которых не определён, разноси в разные группы (у второй product_subtype: null).

ПРАВИЛА ПОДСЧЁТА (строго):
1. Считай только единицы ПЕРЕДНЕГО ряда, обращённые к камере.
2. НЕ считай товар за передним рядом (вглубь полки) и скрытый запас, даже если он виден сверху или сбоку.
3. Мультипаки и термоупаковку, стоящие фоном за передним рядом, поштучно не считай.
4. Каждую видимую переднюю единицу считай ровно один раз.
5. Считай ОТДЕЛЬНО по каждой полке. На каждой полке перечисляй единицы слева направо и считай поштучно — не оценивай число «на глаз».
6. Не пропускай частично видимые единицы с краёв кадра.
7. Перед ответом мысленно локализуй каждую единицу рамкой и считай по рамкам.

РАЗМЕТКА:
- Полки нумеруй сверху вниз: верхняя = 1.
- Расположение указывай словом: слева / центр / справа.

ДОПОЛНИТЕЛЬНО:
- store_code_on_card: если в кадре есть карточка с рукописным кодом (например «231») — впиши его, иначе null.
- store_name, employee_id, date НЕ заполняй — их добавит n8n.
- confidence (0..1) для каждой группы и общий overall_confidence: снижай при плотных, перекрытых, смазанных или снятых под углом кадрах, а также когда подвид пришлось ставить в null.
- notes: коротко, что мешало счёту (блики, ракурс, перекрытия) и какие подвиды не удалось различить.

ВЫВОД: верни строго валидный JSON по заданной схеме. Без markdown и без любого текста вне JSON.
```

## 2. Тело запроса v2 (нода «Gemini Vision», JSON Body)

Отличия: каталог — `file_data` вместо `inline_data`; `file_uri`/`mime_type` приходят с текущего item
(нода «Каталог: Config» стоит прямо перед Gemini — см. BUILD), фото — по ссылке на ноду extract.
Порядок parts не менять: одинаковый префикс (system + каталог) первым, фото — последним. Это условие
для implicit caching.

```json
{
  "systemInstruction": {
    "parts": [{ "text": "<<< системный промпт v2 одной строкой, \n экранированы >>>" }]
  },
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Это СПРАВОЧНИК БРЕНДОВ И ПОДВИДОВ компании. Считай только бренды: Буратино, AI TEA, Chinò, Компотай, Tamga. Подвиды определяй строго по справочнику:" },
      { "file_data": { "mime_type": "{{ $json.mime_type }}", "file_uri": "{{ $json.file_uri }}" } },
      { "text": "Теперь проанализируй ЭТО фото полки и посчитай по правилам и схеме:" },
      { "inline_data": { "mime_type": "image/jpeg", "data": "{{ $('Перевод фото в строку').first().json.data }}" } }
    ]
  }],
  "generationConfig": {
    "temperature": 0,
    "response_mime_type": "application/json",
    "response_schema": {
      "type": "object",
      "properties": {
        "shelves_with_target_product": { "type": "integer" },
        "items": {
          "type": "array",
          "items": {
            "type": "object",
            "properties": {
              "product_name":       { "type": "string" },
              "product_subtype":    { "type": "string", "nullable": true },
              "shelf_index":        { "type": "integer" },
              "shelf_location":     { "type": "string" },
              "front_facing_count": { "type": "integer" },
              "confidence":         { "type": "number" }
            },
            "required": ["product_name","product_subtype","shelf_index","shelf_location","front_facing_count","confidence"]
          }
        },
        "store_code_on_card": { "type": "string", "nullable": true },
        "overall_confidence": { "type": "number" },
        "notes":              { "type": "string" }
      },
      "required": ["shelves_with_target_product","items","overall_confidence"]
    }
  }
}
```

`product_subtype` в required сознательно: nullable + required заставляет модель ЯВНО ставить null,
а не молча пропускать поле.

## 3. Поля → колонки таблицы Data

| Колонка                      | Источник                                  | Статус  |
|------------------------------|-------------------------------------------|---------|
| Магазин                      | вход WF-2                                 | как было|
| Дата                         | n8n (UTC+5)                               | как было|
| Номер агента                 | вход WF-2                                 | как было|
| Название продукта            | `items[].product_name` (теперь чистый бренд) | как было|
| **Подвид**                   | `items[].product_subtype` (null → пусто)  | **НОВАЯ, после «Название продукта»** |
| Номер полки                  | `items[].shelf_index`                     | как было|
| Расположение                 | `items[].shelf_location`                  | как было|
| Количетство товара снаружи   | `items[].front_facing_count`              | как было|
| Уверенность                  | `overall_confidence`                      | как было|
| **Уверенность позиции**      | `items[].confidence`                      | опционально, рекомендую (порог пересъёмки №5 станет точнее) |
| Номер фото                   | `report_id`                               | как было|

## 4. Регрессия перед выкаткой (обязательно)

1. Прогнать фото из `Caspian project/Examples/` на v1 и v2, сравнить СУММЫ front_facing_count по брендам — счёт не должен уехать (правила счёта не менялись, но разбиение на группы стало мельче).
2. Фото с 2+ подвидами одного бренда → отдельные строки с разными «Подвид».
3. Дальний/смазанный кадр → подвид `null` (пустая ячейка), НЕ угаданный подвид.
4. Проверить точное совпадение написания подвидов с канон-списком (диакритика, регистр).
