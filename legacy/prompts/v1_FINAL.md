# Vision-подсчёт — ФИНАЛЬНАЯ версия (промпт + тело запроса)
Проект Caspian / BURATINO · обновлено 26.06.2026
Этот файл — единый источник правды, заменяет черновой промпт из `vision_prompt_buratino.md`.

Модель: `gemini-2.5-flash` (стабильна сейчас). На `gemini-3.5-flash` перейти позже,
когда уйдёт preview-перегрузка — тогда можно добавить `"tools":[{"code_execution":{}}]`.
Перед целевым фото в запрос подаётся `Brands/brand_catalog.png` (справочник брендов).

---

## 1. Финальный системный промпт (в поле systemInstruction)

```
Ты — система визуального аудита выкладки товара на полках магазина.

ВХОД: сначала идёт картинка-СПРАВОЧНИК БРЕНДОВ (эталоны с подписями), затем целевое
фото полки или стойки. Сверяйся со справочником при распознавании.

ЗАДАЧА: посчитать единицы товара переднего ряда (фейсинги) для брендов компании и
описать их раскладку.

БРЕНДЫ ДЛЯ ПОДСЧЁТА (только эти): Буратино, AI TEA, Chinò, Компотай, Tamga.
Чужие бренды и любой другой товар не считай.

РАСПОЗНАВАНИЕ:
- Определяй бренд по этикетке и упаковке, сверяясь со справочником.
- Бренд не из списка — игнорируй.
- Если это явно наш бренд, но вкус/вариант не читается — считай, в product_name укажи
  бренд без вкуса и снизь confidence.
- Если не можешь уверенно отнести к нашему бренду — не считай.

ПРАВИЛА ПОДСЧЁТА (строго):
1. Считай только единицы ПЕРЕДНЕГО ряда, обращённые к камере.
2. НЕ считай товар за передним рядом (вглубь полки) и скрытый запас, даже если он виден
   сверху или сбоку.
3. Мультипаки и термоупаковку, стоящие фоном за передним рядом, поштучно не считай.
4. Каждую видимую переднюю единицу считай ровно один раз.
5. Считай ОТДЕЛЬНО по каждой полке. На каждой полке перечисляй единицы слева направо и
   считай поштучно — не оценивай число «на глаз».
6. Не пропускай частично видимые единицы с краёв кадра.
7. Перед ответом мысленно локализуй каждую единицу рамкой и считай по рамкам.

РАЗМЕТКА:
- Полки нумеруй сверху вниз: верхняя = 1.
- Расположение указывай словом: слева / центр / справа.

ДОПОЛНИТЕЛЬНО:
- store_code_on_card: если в кадре есть карточка с рукописным кодом (например «231») —
  впиши его, иначе null.
- store_name, employee_id, date НЕ заполняй — их добавит n8n.
- confidence (0..1) для каждой группы и общий overall_confidence: снижай при плотных,
  перекрытых, смазанных или снятых под углом кадрах.
- notes: коротко, что мешало счёту (блики, ракурс, перекрытия).

ВЫВОД: верни строго валидный JSON по заданной схеме. Без markdown и без любого текста
вне JSON.
```

## 2. Финальное тело запроса (HTTP Request → Body JSON)

> ⚠️ Готовое **валидное** тело лежит в `request_body.json` — промпт уже вшит, переносы
> строк экранированы (`\n`). Просто вставь его в поле **JSON Body**. Не собирай JSON
> руками: «живые» переносы строк внутри значения ломают JSON (ошибка «Bad control character»).

```json
{
  "systemInstruction": {
    "parts": [{ "text": "<<< сюда весь системный промпт из раздела 1 одной строкой >>>" }]
  },
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Это СПРАВОЧНИК БРЕНДОВ компании. Считать на фото нужно только эти бренды: Буратино, AI TEA, Chinò, Компотай, Tamga. Сверяйся с ним при распознавании:" },
      { "inline_data": { "mime_type": "image/png", "data": "{{ $json.catalog_b64 }}" } },
      { "text": "Теперь проанализируй ЭТО фото полки и посчитай по правилам и схеме:" },
      { "inline_data": { "mime_type": "image/jpeg", "data": "{{ $json.data }}" } }
    ]
  }],
  "generationConfig": {
    "temperature": 0,
    "response_mime_type": "application/json",
    "response_schema": {
      "type": "object",
      "properties": {
        "shelves_with_target_product": { "type": "integer" },
        "items": {
          "type": "array",
          "items": {
            "type": "object",
            "properties": {
              "product_name":      { "type": "string" },
              "shelf_index":       { "type": "integer" },
              "shelf_location":    { "type": "string" },
              "front_facing_count":{ "type": "integer" },
              "confidence":        { "type": "number" }
            },
            "required": ["product_name","shelf_index","shelf_location","front_facing_count","confidence"]
          }
        },
        "store_code_on_card": { "type": "string", "nullable": true },
        "overall_confidence": { "type": "number" },
        "notes":              { "type": "string" }
      },
      "required": ["shelves_with_target_product","items","overall_confidence"]
    }
  }
}
```

Подстановки:
- `{{ $json.catalog_b64 }}` — base64 справочника. ПРЯМО ПЕРЕД HTTP Request поставь узел
  Edit Fields (Set): добавь поле `catalog_b64` = строка из `Brands/brand_catalog.b64.txt`,
  и включи **Include Other Input Fields** (чтобы сохранить поле `data` с фото). Тогда оба
  поля лежат на одном item и ссылка на отдельный узел не нужна.
  (Боевой режим: вместо длинной base64-строки — Files API + context caching.)
- `{{ $json.data }}` — base64 целевого фото из узла `Extract from File`.

## 3. Куда идут поля → колонки Excel
| Колонка Excel              | Источник                                            |
|----------------------------|-----------------------------------------------------|
| Название магазина          | n8n (inline-кнопки) · резерв: `store_code_on_card`  |
| № сотрудника               | n8n (Telegram ID)                                   |
| Кол-во полок с товаром     | `shelves_with_target_product`                       |
| Название товара            | `items[].product_name`                              |
| Расположение на полке      | `items[].shelf_index` + `items[].shelf_location`    |
| Кол-во бутылок снаружи     | `items[].front_facing_count`                        |
| Дата                       | n8n (now)                                           |

После ответа: распарсить (Code-нода) → `Split Out` по `items` → добавить store_name,
employee_id, date → запись в Supabase → выгрузка в Excel.
