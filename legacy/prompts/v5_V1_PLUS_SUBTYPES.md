# Промпт v5 — v1 + минимальный блок подвидов

## 1. Что это

Промпт v1 (`vision_prompt_FINAL.md`) — лучший по счёту из всех проверенных — взят дословно. Добавлен минимум:

1. ЗАДАЧА: «…определить подвид каждой группы…».
2. РАСПОЗНАВАНИЕ: правило v1 «бренд ясен, вкус не читается — считай» дополнено «…поставь product_subtype: null».
3. Новый блок ПОДВИДЫ после правил подсчёта: канон-имена (только имена, одной строкой на бренд), Tamga → null, банка=бутылка, «сомневаешься → null, единицы остаются в счёте», разные подвиды = разные группы.
4. Chinò → Chino (финальное решение по диакритике), в product_name — только бренд.
5. Схема — как в v2/v3 (product_subtype обязателен, nullable). Правок n8n-нод не нужно.

Сознательно НЕ добавлено (в этом смысл эксперимента — минимальная дельта от v1): словесные описания 21 подвида, пары-близнецы, двухшаговая процедура. Ожидаемая цена: подвиды будут чаще null или с ошибками близнецов. Это ок — сейчас чиним счёт; если счёт вернётся, точечно добавим ТОЛЬКО блок близнецов и снова замерим.

## 2. Как читать результат теста (матрица интерпретации)

| Результат v5 | Вывод | Следующий шаг |

## 3. Гипотеза «каталог по ссылке» — разбор

**Ссылка (file_uri) vs инлайн (base64) — не механизм.** После аплоада в Files API модель получает те же самые токены изображения, что и при inline_data; транспорт на качество не влияет. Перекладывать PDF в base64 — не стоит потраченного времени.

**Но нить правильная: вместе с промптом сменился САМ каталог.** v1 (лучший счёт) работал с ОДНИМ PNG `brand_catalog.png`; начиная с v2 — 5-страничный PDF. Два подозреваемых механизма:
1. PDF-страницы растеризуются с более низким эффективным разрешением, чем отдельные изображения, — мелкие различители (крышки, плоды на этикетках) в эталонах мылятся;
2. 5 страниц × 22 карточки = больше визуального контекста, который размывает внимание к целевому фото.

**Диагностика за 5 минут (до любых переделок):** клонируй ноду «Gemini Vision (3.5-flash)», в jsonBody замени последние два part'а (текст + фото) на один текстовый: «Опиши справочник постранично: перечисли каждую карточку и её подпись ДОСЛОВНО, укажи цвет крышки каждого товара», убери response_schema и response_mime_type. Если модель не может дословно прочитать подписи и цвета крышек — гипотеза разрешения подтверждена, идём в media_resolution/PNG. Если читает всё — каталог невиновен, дело в промпте/модели.

**Лечение, если подтвердится (по одному за раз):**
1. `"media_resolution": "MEDIA_RESOLUTION_HIGH"` в generationConfig — одна строка, поднимает разрешение обработки и каталога, и фото. Синтаксис/поддержку проверить по докам generateContent (если 400 — попробовать camelCase `mediaResolution` или убрать). Дороже по input-токенам.
2. PNG-каталог: экспорт из Фигмы постранично в PNG высокого разрешения, WF-3 заливает 5 файлов, Config хранит 5 строк, в contents — 5 file_data-частей. Больше правок (WF-3 + Config + jsonBody), делать только если п.1 не хватило.
