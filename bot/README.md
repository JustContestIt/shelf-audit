# shelf-audit-bot — Telegram-бот торгового агента

Тонкий клиент HTTP API на aiogram 3. Вся логика живёт в графе. Бот заменяет Main WF v9.2 из n8n.

## Сценарий

1. `/start` → если Telegram id агента ещё не известен, бот просит поделиться телефоном (кнопкой или текстом
   `+7 …` / `8 …`). Номер нормализуется и сверяется с листом агентов (`POST /agents/auth`), затем
   Telegram id привязывается к агенту.
2. Маршрут дня → выбор точки: кнопки по 8 на страницу, в кнопке название и адрес. `/store` — сменить точку.
   Старый 15-минутный TTL заменён явной командой.
3. Фото, альбом (`media_group`, ожидание 2 с) или картинка документом → `POST /photos`. Каждое фото — свой
   отчёт. Бот показывает ход обработки: «ищу товар на полках…», «уточняю вкусы…».
4. Карточка: строки по полкам, «не опознано», ⚠️ у `needs_review`, «Чужой товар рядом (не в счёте)».
   Кнопки ✅ «Всё верно» и 🔄 «Переснять».
5. ✅ → `POST /reports/{id}/review {"action":"approve"}`. 🔄 → следующее фото из этого чата уходит как
   пересъёмка того же отчёта (`/reports/{id}/retake`).

Супервайзер видит те же отчёты в кабинете и может поправить строки. Утверждение агентом — это «я согласен со
счётом», а не финальная проверка.

## Запуск

Нужен **новый тестовый бот** от @BotFather. Боевой токен использовать нельзя: его нужно отозвать.

```bash
cd bot && uv pip install -e ".[dev]"
TELEGRAM_BOT_TOKEN=... API_BASE_URL=http://localhost:8000 shelf-audit-bot
# или в Docker:
docker compose --profile bot up -d bot
```

Переменные: `TELEGRAM_BOT_TOKEN`, `API_BASE_URL`, `API_TOKEN` (если API закрыт). Без токена бот сразу
завершается с понятным сообщением.

Для демо агенты и точки вымышленные (`backend/app/storage/demo_seed.json`). Настоящий лист маршрутов
выгружается из системы заказчика (BACKLOG №26).

## Тесты

`pytest -q` проверяет тексты карточек и клавиатуры: пагинация точек, callback-данные, прогресс. Живой Telegram в
этой среде не проверялся: нет токена тестового бота.
